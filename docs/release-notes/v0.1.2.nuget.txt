MediaToolkit.NET 0.1.2 - the FFmpeg backend release.

Audio encoding did not work at all in 0.1.1, on any FFmpeg version, and fixing
that uncovered a second defect underneath it in the struct offsets themselves.
Both are fixed here, FFmpeg 8.x and 9.x are supported alongside 7.x, and a test
suite now checks every offset against the library that is actually installed.

The README on this page covers what the library does and what it needs at
runtime. These notes cover only what is specific to this release.

FIXED

- Audio encoding never worked. The channel count was set through the "ac"
  AVOption, which has not existed on AVCodecContext since FFmpeg 7 removed the
  old channel API; the encoder then refused to open for want of a layout. The
  same mistake sat in the startup probe of the AVFrame audio fields, which
  switched audio encoding off wholesale. The layout now travels through
  ch_layout.
- The AVStream offsets were wrong in every FFmpeg from 6 to 9. codecpar was read
  at 208 where it lives at 16, and time_base, start_time, duration and
  avg_frame_rate were each eight bytes short. The muxer writes codec parameters
  through codecpar, so adding a stream to an output wrote through a wild pointer.
  A new stream is now checked before anything is written through it.
- Channel layouts were guessed as (1 << channels) - 1, which gives 3.1 for four
  channels rather than quad. The layout of a bare channel count now comes from
  av_channel_layout_default.
- Encoder flags were assigned rather than accumulated, dropping the global header
  bit whenever a second flag was set.
- .mka and .mks are the same muxer as .mkv and now ask for a global header too.

ADDED

- FFmpeg 8.x and 9.x beside 7.x. The loader matches the versions it got against a
  table of release series and refuses a mixture belonging to none of them.
- AC-3 and DTS. The DCA encoder is experimental in FFmpeg and is opened as such
  without the caller having to say so.
- PCM at 8, 16, 24 and 32 bits.
- Variable bitrate, through AudioEncodingSettings.Quality, on the scale -q:a uses.
- Per-stream EncoderName and Options, which name an encoder outright and pass
  AVOptions to that stream alone.
- Stated channel layouts: the ChannelLayout constants and AudioFormat.ChannelMask.
  Six channels are 5.1 twice over, the back arrangement and the side one, and
  only a mask tells an encoder which.
- 134 unit tests and 43 integration tests, the latter checking every struct field
  read by offset against the installed library.

CHANGED

- Six channels with no stated layout now default to 5.1 side, as
  av_channel_layout_default does, rather than 5.1 back. Ask for
  ChannelLayout.FivePoint1Back where the back arrangement is meant.
- AudioFormat takes a fourth, optional ChannelMask. Source-compatible.
- AbiLayout.CodecContextTimeBase and CodecContextPixFmt are properties rather
  than constants, and PrepareAudioFrame takes the channel mask.
- FFmpegLibraries.AvUtilMajor, AvCodecMajor and AvFormatMajor are gone;
  FFmpegLibraries.Generation and FFmpegGeneration.Known replace them.

VERIFIED BY RUNNING

On Windows 11 against FFmpeg 9.0.1: AC-3 at one, four and six channels, DTS, AAC
at a fixed rate and at a quality, and PCM at 8, 16, 24 and 32 bits, each encoded
into Matroska and read back as the codec, rate and channel count it was given;
MJPEG video encoded and muxed, which is the path that writes through
AVStream::codecpar; and every hard-coded offset checked against the running
library. The offset tests were themselves checked by breaking three offsets on
purpose, each of which failed loudly and corrupted nothing.

NOT EXERCISED YET

- FFmpeg 7.x and 8.x have not been run. Their entries in the series table were
  read with offsetof against the headers of n7.1.5 and n8.1.2, and they name the
  same fields 9.x uses, but no library of those series was loaded. Running
  "dotnet test" on a machine that has one confirms them.
- The Linux, macOS and mpv backends have still never been run.
- Media Foundation video recording is still untested; audio recording works.

That is why this is still 0.1.x. The public API may still change.

KNOWN LIMITATIONS

- An encoder's own constraints are the caller's to meet: DCA takes only the side
  arrangement of 5.1 and refuses stereo below 384 kbps, and AC-3 does not do 7.1.
  The failure names the encoder, the sample rate and the layout asked for. The
  FFmpeg command line hides this behind an automatic conversion filter; this API
  does not.
- Matroska stores no channel mask, so PCM read back from it reports an
  unspecified layout. The mask matters for encoding, not for what the container
  records.
- MacOSBackend cannot write files, because AVAssetWriter is not wrapped.
- FFmpegPlayer only decodes: no renderer and no audio output.
- Only the mpv client API is wrapped; the render API is not.
- DirectShow is wrapped for device enumeration only, with no filter graph.
