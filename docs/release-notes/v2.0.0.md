# MediaToolkit.NET 2.0.0

Four backends grow. `MediaToolkitNet.FFmpeg` gains the API FFmpeg added in 8.x, 9.0 and 9.1; `MediaToolkitNet.Mpv` gains its
node API, hooks and stream callbacks; `MediaToolkitNet.Windows` gains window and monitor capture, process audio, audio and
camera controls and a Media Foundation transcoder; `MediaToolkitNet.GStreamer` gains a message bus, signals, `appsrc`, typed
properties, a recorder, a player and pipelines built by hand. The shared interfaces are unchanged, and everything new is optional and checked at run
time, so 2.0.0 still runs on FFmpeg 7.1 and the FFmpeg features simply report themselves as absent.

## Upgrading from 1.0.0

There is no 1.1.0 release: what was prepared under that number is part of 2.0.0. The major number changes because of these:

- `FFmpegDecoder.Open` has a new optional parameter, `nativeDsd`. Source that calls it compiles unchanged; assemblies
  built against 1.0.0 have to be recompiled.
- `WindowsBackend` now declares `Probing`, `Transcoding` and `Playback`, and `GStreamerBackend` now declares `Recording` and
  `Playback`. Code that picks a backend by its capabilities can get one it did not get before.
- A file mpv cannot play now raises `MpvPlayer.Failed`.

## Added to MediaToolkitNet.Mpv

mpv's node API: `MpvNode`, `MpvPlayer.GetPropertyNode` / `SetPropertyNode` / `CommandNode` (named arguments and
command results), and typed readers `GetTracks`, `GetChapters` and `GetMetadata`, `ObserveProperty`, `GetCommands` / `GetPropertyNames` / `HasCommand` / `HasOption` (what this mpv can do), `Failed` for a file
mpv could not play, `AddHook` (`on_load` and the other mpv hooks, with `Defer` / `Continue`), `CommandNodeAsync` / `CommandAsync` (asynchronous
commands with cancellation), `Open(Stream)` and `RegisterStreamProtocol` (mpv reads a .NET stream or a protocol you define through `stream_cb`), and
`TakeScreenshot` (mpv's `screenshot-raw`: a frame
after mpv's filters, scaling and subtitles, as BGRA, RGBA, BGR0 or 16-bit RGBA). Tested on Windows (libmpv from
winget) and Debian (client API 2.5).

## Added to MediaToolkitNet.Windows

| Feature | API |
|---|---|
| Monitor capture from the GPU (DXGI Desktop Duplication) | `DesktopCapture` |
| Window and monitor capture from the compositor (Windows.Graphics.Capture, Windows 10 1903+) | `GraphicsCapture` |
| Sound of one process, or of everything but it (Windows 10 2004+) | `WasapiCapture.ForProcess`, `ProcessLoopbackMode` |
| Endpoint volume, mute and peak meter; per-program sessions; device notifications | `AudioEndpointVolume`, `AudioSession`, `AudioDeviceNotifications` |
| Camera pan, tilt, zoom, exposure, focus and the like | `MediaFoundationVideoCapture.Controls` |
| Probing and transcoding through Media Foundation | `MediaFoundationProber`, `MediaFoundationTranscoder` (backend `mediafoundation`) |
| Playback on the Media Engine: Windows plays the sound, frames come back as BGRA | `MediaFoundationPlayer` |
| Exclusive mode and the short periods of `IAudioClient3`, capture and playback | `WasapiMode` on `WasapiRenderer` and `WasapiCapture`, `PeriodFrames` |

`WindowsBackend` now declares `Probing` and `Transcoding` as well. The transcoder reports what it cannot do as errors and
what it does approximately as warnings, and drops nothing silently.

## Added to MediaToolkitNet.GStreamer

- **Bus and signals.** `pipeline.Bus` (`GStreamerBus`) delivers parsed messages (errors, warnings, state changes, tags,
  buffering, element and application messages) with a `Mask`, `PostApplication` and a `Failed` event for a throwing handler.
  `GStreamerElement.Connect` attaches a handler to any signal (`pad-added`, `handoff`, `need-data`, `notify::property`) with
  typed arguments and a settable return value.
- **`appsrc`.** `pipeline.GetSource` returns a `GStreamerSource`: `PushVideo`, `PushAudio`, `Push`, `EndOfStream`, `NeedData`
  and `EnoughData`. Video rows are repacked to GStreamer's strides; a frame of another size or format is refused.
- **Typed properties.** `GStreamerElement.SetValue`, `GetValue` and `Get<T>` for booleans, integers, floats, strings, enums
  and flags.
- **Recorder.** `GStreamerRecorder` is an `IMediaRecorder`: one `appsrc` per stream into the encoder and muxer the
  transcoder already knows, with `EncoderName` for a hardware encoder (`nvh264enc` and `nvh265enc` are mapped), `SegmentDuration`
  for `splitmuxsink`, and the output written beside the target and renamed by `Stop`.
- **Streaming output.** `GStreamerRecorder` also writes an HLS playlist with segments (a path ending in `.m3u8`) and MPEG-TS over
  SRT (`srt://host:port?mode=listener`), with `DrainTime` so that SRT delivers the last frames before the connection closes.
- **Several outputs.** `GStreamerRecorder.AddOutput` sends one encoding to files, an HLS playlist and SRT at the same time.
- **Audio mixer.** `GStreamerAudioMixer` adds inputs with a volume and a mute each (changeable while it runs), converting and
  resampling each to the output format.
- **Graph dump.** `GStreamerPipeline.ToDot(GstGraphDetails)` returns the pipeline as Graphviz text.
- **Compositor.** `GStreamerCompositor` lays layers (place, size, alpha, stacking order, changeable while it runs) into one BGRA picture, and
  `GStreamerElement.SetPadValue` sets a property of any pad.
- **X11 capture.** `GStreamerScreenCapture` (`ForScreen`, `ForRegion`, `ForWindow`) is an `IVideoCapture` on `ximagesrc`. It keeps an
  X server error (a window that closed or never existed) from ending the process and reports it through `Failed`.
- **Player.** `GStreamerPlayer` is an `IMediaPlayer` on `playbin3` that hands frames back as `Bgra32` and `S16`, paced by the
  clock. `VideoSink` and `AudioSink` (`ximagesink`, `pulsesink`, any sink description) make the output real, and
  `VideoWindowHandle` draws into an X11 window of yours. A fault is reported once and ends the use of the player until
  `Open`; a stream with no length cannot seek or start over.
- **Pipelines by hand.** `GStreamerPipeline.Create`, `Add` and `GStreamerElement.Link` build a pipeline without a
  description. `Link` takes request pads from an element such as `tee`, and links a pad that `pad-added` announced by its
  name. `AddBin` adds a part of a description as one element, and `Unlink` and `Remove` take one out again.
- **Caps, structures, action signals.** `GStreamerCaps` and `GStreamerStructure` are typed copies, given by `GetValue` and
  signal arguments and taken by `SetValue`. `GStreamerElement.Emit` calls an action signal (`split-now`, `get-stats`) and
  returns its answer; a signal that answers with a reference, such as a sample, is refused.
- **Probes and running pipelines.** `GStreamerElement.AddProbe` watches, drops or blocks what passes a pad.
  `SyncStateWithPipeline`, `EndOfStream(pad)`, `ReleasePad` and a `Remove` that stops what it takes out let a branch be
  added to and removed from a playing pipeline, recording while previewing for one.
- **Encoded data.** `GStreamerSink.TryPullData` gives a sample's bytes with its presentation and decode times, duration,
  key frame and header flags, and caps.
- **Seeking.** `GStreamerPipeline.Seek(start, stop, rate, flags)` plays a range, faster, slower or backwards; with
  `GstSeekFlags.Segment` the bus reports `SegmentDone`, so a range can be looped.
- **Introspection.** `GStreamerElements.Describe` lists a factory's properties and pad templates; `GetPadValue` and
  `GetElement` read pad properties and elements a property holds; fraction and array properties are read; element messages
  carry typed `Details`; `AddDataProbe` reads the bytes of the buffers on a pad.
- **Stepping, clocks, queries, events.** `GStreamerPipeline.Step`, `ClockTime`, `BaseTime`, `RunningTime`,
  `SynchronizeWith`, `SetLatency`, `RecalculateLatency`, `QueryLatency`, `QuerySeeking` and `QueryBuffering`;
  `GStreamerElement.SendEvent` for custom events and `ForceKeyFrame`.
- **Ranks, plugins, messages, log.** `GStreamerElements.GetRank`, `SetRank` and `ScanPlugins`; QoS, progress,
  table-of-contents and stream-start messages arrive parsed (QoS is delivered only when the mask asks for it);
  `GStreamerLog.Subscribe` delivers GStreamer's debug log.
- **Processing while running.** Mixer inputs and compositor layers are added and removed while they run;
  `Animate`, `AnimatePad` and `ClearAnimation` move properties over stream time; `SetActivePad` switches an
  `input-selector`; `GStreamerPreRecordGate` keeps the last seconds of a branch for a recording that starts late.
- **Devices and stream collections.** `GStreamerDeviceMonitor` lists devices, raises `DeviceAdded` and
  `DeviceRemoved`, and `GStreamerPipeline.Add(device)` makes the element; stream collection messages list the streams.
  A bus mask no longer lets stream collections through by accident.
- **RTSP server.** `GStreamerRtspServer` serves pipeline descriptions at mount paths, with a callback to reach the
  elements of each media (an `appsrc` to feed, for one). It needs `gst-rtsp-server`, listens on the loopback unless told
  otherwise, and has no authentication or encryption. Clients use UDP or TCP, which `transports` can limit.
- **WebRTC.** `GStreamerWebRtcPeer`: send and receive through parts of its pipeline, offers, answers and ICE candidates
  as text, and `ExchangeAsync` for WHIP publishing and WHEP playing. A received stream says what it is (`Caps`).
- **Without copies.** `GStreamerSource.PushNoCopy` wraps the application's memory and reports when it is free again;
  `PushDmaBuf` passes a DMABuf's descriptor on, and `GStreamerData.DmaBufFd` gives it back out of a pipeline.
- **Elements in .NET.** Derive from `GStreamerTransform` and `Register` it: an element that changes or drops buffers in
  place, used by name in any pipeline.
- **End of stream.** `GStreamerPipeline.EndOfStream` ends a live pipeline so that muxers finish their files.
- `GStreamerBackend` declares `Recording` and `Playback`, and `gst-rec` and `gst-play` in the sample try them.

## Fixed

Both in `MediaToolkitNet.GStreamer`, and both there since 1.0.0:

- A trimming transcode now and then failed with `Internal data stream error`: the seek to the start could be sent while
  the demuxer was still passing its first buffers on. It now waits for every branch to have data, at most two seconds.
- `GStreamerProber` now and then returned a stream without its language and title, a subtitle track's most often, because
  `GstDiscoverer` finished before the stream's tags reached it. Such a file is now read again, up to three times.

## Changed

- `MediaToolkitNetBackends.Select(Recording)` and `Select(Playback)` order GStreamer after every other backend, so declaring
  the two roles does not change the default on Linux: FFmpeg still records and mpv still plays.
- `Select(Playback)` also orders the Windows backend after mpv and FFmpeg, so the default player on Windows is unchanged.

## Tested

Windows 11 with FFmpeg 9.1 (a development build) and 9.0.1, and Debian 13 with FFmpeg 7.1.5 and 9.1, mpv 0.42 and
GStreamer 1.26.2 (WSL). Features missing from a build skip their tests there. Every new struct layout is confirmed at run
time and the feature turns itself off when the check fails. Stream group membership is cross-checked against the
context's own streams.

GStreamer output is tested from outside the library under WSLg: a window's pixels are read back from the X server, and the
sound is recorded from the sound server's monitor (a 440 Hz tone reads the level it should, and a tenth of the volume reads
exactly 20 dB lower). The recorder's output is read back with FFmpeg's prober, reader and program, and `nvh264enc` was run
on an RTX 4070.

For 2.0.0 the unit tests were run again on Windows 11 and the GStreamer tests on Debian 13 with GStreamer 1.26.2 under
WSL (all passed but one that needs NVENC, which was not there).

## Known limits

- WASAPI exclusive and low-latency modes: tried on one machine's default endpoints. Exclusive output was checked by ear
  only (loopback cannot see it), and that machine's output offers no shared period under 10 ms, so a short low-latency period was
  checked on capture only.
- Several outputs: an added SRT output drops what nobody receives; the memory a paced output can build up when frames are pushed
  faster than real time is not limited; subtitles and per-output settings are not offered.
- Media Foundation player: no audio frames and no window output; it opens what Windows has codecs for. Tried with H.264 and AAC
  in MP4 from a local file, not with network sources.
- `Reconfigure` accepts only options FFmpeg marks as changeable at run time. FFmpeg 9.1 crashes on the others
  (a NULL dereference in `avcodec_encode_reconfigure`), so they are refused before the call.
- A bitstream filter graph takes graph filters only (`lcevc_merge`, source, sink); classic filters are refused.
- DSD is decoder-level only: the shared `SampleFormat` has no DSD value, so readers, recorder and transcoders stay PCM
  (DSD files still decode to float there, as before). FFmpeg has no PCM to DSD conversion.
- Tile grid and layered video group parameters were not tested against a real file; IAMF groups were.
- Not covered: Linux and macOS with FFmpeg 8 or 9.
- Windows: device notification events (`AudioDeviceNotifications`) are registered and unregistered but never fired, since no
  test can make a device come and go; rotated monitors, hiding the capture border (Windows 11 only), a window on another GPU and
  a protected window are not covered; Media Foundation does not say whether the hardware or Microsoft's encoder ran, and its
  AAC encoder takes only 44.1 and 48 kHz, one or two channels and 96, 128, 160 or 192 kb/s.
- GStreamer: the recorder converts nothing for the caller, takes no subtitles, and only NVENC is mapped among hardware
  encoders; NVENC refuses frames under 160x64 and says only "not-negotiated". The player's window output is X11 only, and the
  sound test is tied to WSLg's `RDPSink`; Wayland, OpenGL sinks, buffering and QoS messages, and signals that carry caps or
  structures are not covered. Nothing GStreamer has run on macOS or Windows.
- GStreamer audio mixer: mono and stereo only were tried, as were synthetic tones; a clocked live mix and more than two channels were not.
- GStreamer compositor: layers are solid-colour in the tests, so scaling quality, the pixel formats other than BGRA, a live (clocked) mix
  and several outputs were not tried.
- GStreamer screen capture: X11 only, tested on WSLg with windows the test makes itself; Wayland-native clients are not seen, nothing was
  tried on a real Xorg desktop, with several monitors or with the pointer drawn, and the error handler is process-wide.
- GStreamer streaming: only HLS (checked with ffmpeg and the player) and SRT over the loopback (checked by recording what a
  plain `srtsrc` receives and decoding it with ffmpeg) are offered. RTMP, RTSP and UDP are not, and SRT to another machine, in
  caller mode or with a passphrase was not tried. SRT in live mode can drop frames on a real network.
- GStreamer changes to a playing pipeline are low level, and only adding and removing a `tee` branch was tried; a probe can
  read a buffer, not change it. A bin cannot be put together element by element.
- GStreamer structures are made and changed through their text, and a range or another type without a managed counterpart
  is given as text.
- GStreamer seeking was tried on Matroska with intra-only video; other rates than 1 and -1, and trick-mode flags, were not
  tried.
- GStreamer clocks: sharing was tried between two live pipelines in one process; network clocks are not offered. The live
  flag of `QueryLatency` is set by a sink that keeps to the clock, whatever the source.
- GStreamer plugin scanning was tried only with a directory holding none; the debug log and element ranks belong to the
  whole process.
- GStreamer: a removed mixer input or layer keeps its index empty, and a running mixer or compositor waits for every input
  it has. The pre-record gate opens once and was tried with VP8. Animation needs `libgstcontroller`. No fallback source.
- GStreamer device monitoring: listing was tried with PulseAudio devices under WSLg; a device coming or going was not, and
  neither were cameras.
- GStreamer RTSP server: no authentication, TLS, multicast or recording by clients. MJPEG, H.264, H.265, VP8, VP9, Opus and
  AAC were tried over the loopback only, not over a real network; FFmpeg 7.1 does not read the VP9 stream.
- GStreamer WebRTC: tried between two peers on one machine with VP8, VP9, H.264 and Opus, and over HTTP against a test endpoint, not against
  a browser or a media server; STUN was not tried, TURN, data channels and ending a WHIP or WHEP session are not offered.
- GStreamer zero-copy: DMABuf was tried with `memfd` descriptors only, not with buffers of a graphics device or camera;
  OpenGL and CUDA memory are not exposed.
- GStreamer elements in .NET: in-place transforms only, with the same format in and out and no properties of their own; a
  registration lasts as long as the process.
