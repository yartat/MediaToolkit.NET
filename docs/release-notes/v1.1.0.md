# MediaToolkit.NET 1.1.0

Four backends grow. `MediaToolkitNet.FFmpeg` gains the API FFmpeg added in 8.x, 9.0 and 9.1; `MediaToolkitNet.Mpv` gains its
node API, hooks and stream callbacks; `MediaToolkitNet.Windows` gains window and monitor capture, process audio, audio and
camera controls and a Media Foundation transcoder; `MediaToolkitNet.GStreamer` gains a message bus, signals, `appsrc`, typed
properties, a recorder and a player. The shared interfaces are unchanged, and everything new is optional and checked at run
time, so 1.1.0 still runs on FFmpeg 7.1 and the FFmpeg features simply report themselves as absent.

## Added

| Feature | API | Needs |
|---|---|---|
| Capability flags | `FFmpegFeatures` | any |
| Frame side data | `FFmpegFrameDetails` (`SideData`, `HasSideData`), `TryReadNext` / `TryReadAt` overloads | any |
| EXIF | `FFmpegExif.Parse`, `FFmpegFrameDetails.Exif()` | 8.1 |
| MIME codec string | `FFmpegDemuxer.MimeCodecString` | 8.1 |
| Synchronous decoding | `FFmpegDecoder.ReceiveFrame(frame, synchronous)` | 8.1 |
| Encoder reconfiguration | `FFmpegRecorder.Reconfigure` | 9.1 |
| Bitstream filter graphs | `FFmpegBitstreamFilterGraph` | 9.1 |
| HDR gain maps | `FFmpegGainMap` (ISO 21496-1 round trip, validation, frame side data) | 9.1 |
| Downmix matrices | `FFmpegDownmixMatrix` | 9.1 |
| DSD | `FFmpegDecoder.Open(..., nativeDsd: true)`, `AVSampleFormat.Dsd`, `FFmpegFeatures.NativeDsd` | 9.1 |
| Windows handle input | `FFmpegDemuxer.OpenHandle(SafeFileHandle)`, `FFmpegFeatures.HandleInput` | 9.1, Windows |
| Stream groups | `FFmpegDemuxer.StreamGroups` | any (newer group types need newer FFmpeg) |
| Typed filters | `FFmpegNewFilters`: `ColorDetect`, `LatticePal`, `Whisper`, `GainMap` | the filter's release |

## Added to MediaToolkitNet.Mpv

mpv's node API: `MpvNode`, `MpvPlayer.GetPropertyNode` / `SetPropertyNode` / `CommandNode` (named arguments and
command results), and typed readers `GetTracks`, `GetChapters` and `GetMetadata`, `ObserveProperty`, `GetCommands` / `GetPropertyNames` / `HasCommand` / `HasOption` (what this mpv can do), `Failed` for a file
mpv could not play, `AddHook` (`on_load` and the other mpv hooks, with `Defer` / `Continue`), `CommandNodeAsync` / `CommandAsync` (asynchronous
commands with cancellation), `Open(Stream)` and `RegisterStreamProtocol` (mpv reads a .NET stream or a protocol you define through `stream_cb`), and
`TakeScreenshot` (mpv's `screenshot-raw`: a frame
after mpv's filters, scaling and subtitles, as BGRA, RGBA, BGR0 or 16-bit RGBA). Tested on Windows (libmpv from
winget) and Debian (client API 2.5).

## Added to MediaToolkitNet.Windows

| Feature | API |
|---|---|
| Monitor capture from the GPU (DXGI Desktop Duplication) | `DesktopCapture` |
| Window and monitor capture from the compositor (Windows.Graphics.Capture, Windows 10 1903+) | `GraphicsCapture` |
| Sound of one process, or of everything but it (Windows 10 2004+) | `WasapiCapture.ForProcess`, `ProcessLoopbackMode` |
| Endpoint volume, mute and peak meter; per-program sessions; device notifications | `AudioEndpointVolume`, `AudioSession`, `AudioDeviceNotifications` |
| Camera pan, tilt, zoom, exposure, focus and the like | `MediaFoundationVideoCapture.Controls` |
| Probing and transcoding through Media Foundation | `MediaFoundationProber`, `MediaFoundationTranscoder` (backend `mediafoundation`) |

`WindowsBackend` now declares `Probing` and `Transcoding` as well. The transcoder reports what it cannot do as errors and
what it does approximately as warnings, and drops nothing silently.

## Added to MediaToolkitNet.GStreamer

- **Bus and signals.** `pipeline.Bus` (`GStreamerBus`) delivers parsed messages (errors, warnings, state changes, tags,
  buffering, element and application messages) with a `Mask`, `PostApplication` and a `Failed` event for a throwing handler.
  `GStreamerElement.Connect` attaches a handler to any signal (`pad-added`, `handoff`, `need-data`, `notify::property`) with
  typed arguments and a settable return value.
- **`appsrc`.** `pipeline.GetSource` returns a `GStreamerSource`: `PushVideo`, `PushAudio`, `Push`, `EndOfStream`, `NeedData`
  and `EnoughData`. Video rows are repacked to GStreamer's strides; a frame of another size or format is refused.
- **Typed properties.** `GStreamerElement.SetValue`, `GetValue` and `Get<T>` for booleans, integers, floats, strings, enums
  and flags.
- **Recorder.** `GStreamerRecorder` is an `IMediaRecorder`: one `appsrc` per stream into the encoder and muxer the
  transcoder already knows, with `EncoderName` for a hardware encoder (`nvh264enc` and `nvh265enc` are mapped), `SegmentDuration`
  for `splitmuxsink`, and the output written beside the target and renamed by `Stop`.
- **Player.** `GStreamerPlayer` is an `IMediaPlayer` on `playbin3` that hands frames back as `Bgra32` and `S16`, paced by the
  clock. `VideoSink` and `AudioSink` (`ximagesink`, `pulsesink`, any sink description) make the output real, and
  `VideoWindowHandle` draws into an X11 window of yours. A fault is reported once and ends the use of the player until
  `Open`; a stream with no length cannot seek or start over.
- `GStreamerBackend` declares `Recording` and `Playback`, and `gst-rec` and `gst-play` in the sample try them.

## Changed

- `MediaToolkitNetBackends.Select(Recording)` and `Select(Playback)` order GStreamer after every other backend, so declaring
  the two roles does not change the default on Linux: FFmpeg still records and mpv still plays.

## Tested

Windows 11 with FFmpeg 9.1 (a development build) and 9.0.1, and Debian 13 with FFmpeg 7.1.5 and 9.1, mpv 0.42 and
GStreamer 1.26.2 (WSL). Features missing from a build skip their tests there. Every new struct layout is confirmed at run
time and the feature turns itself off when the check fails. Stream group membership is cross-checked against the
context's own streams.

GStreamer output is tested from outside the library under WSLg: a window's pixels are read back from the X server, and the
sound is recorded from the sound server's monitor (a 440 Hz tone reads the level it should, and a tenth of the volume reads
exactly 20 dB lower). The recorder's output is read back with FFmpeg's prober, reader and program, and `nvh264enc` was run
on an RTX 4070.

## Known limits

- `Reconfigure` accepts only options FFmpeg marks as changeable at run time. FFmpeg 9.1 crashes on the others
  (a NULL dereference in `avcodec_encode_reconfigure`), so they are refused before the call.
- A bitstream filter graph takes graph filters only (`lcevc_merge`, source, sink); classic filters are refused.
- DSD is decoder-level only: the shared `SampleFormat` has no DSD value, so readers, recorder and transcoders stay PCM
  (DSD files still decode to float there, as before). FFmpeg has no PCM to DSD conversion.
- Tile grid and layered video group parameters were not tested against a real file; IAMF groups were.
- Not covered: Linux and macOS with FFmpeg 8 or 9.
- Windows: device notification events (`AudioDeviceNotifications`) are registered and unregistered but never fired, since no
  test can make a device come and go; rotated monitors, hiding the capture border (Windows 11 only), a window on another GPU and
  a protected window are not covered; Media Foundation does not say whether the hardware or Microsoft's encoder ran, and its
  AAC encoder takes only 44.1 and 48 kHz, one or two channels and 96, 128, 160 or 192 kb/s.
- GStreamer: the recorder converts nothing for the caller, takes no subtitles, and only NVENC is mapped among hardware
  encoders; NVENC refuses frames under 160x64 and says only "not-negotiated". The player's window output is X11 only, and the
  sound test is tied to WSLg's `RDPSink`; Wayland, OpenGL sinks, buffering and QoS messages, and signals that carry caps or
  structures are not covered. Nothing GStreamer has run on macOS or Windows.
