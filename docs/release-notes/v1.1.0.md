# MediaToolkit.NET 1.1.0

`MediaToolkitNet.FFmpeg` gains the API FFmpeg added in 8.x, 9.0 and 9.1. It is FFmpeg-only: nothing was added to
the shared interfaces, and the other backends are unchanged. Everything is optional and checked at run time, so 1.1.0
still runs on FFmpeg 7.1 and the features simply report themselves as absent.

## Added

| Feature | API | Needs |
|---|---|---|
| Capability flags | `FFmpegFeatures` | any |
| Frame side data | `FFmpegFrameDetails` (`SideData`, `HasSideData`), `TryReadNext` / `TryReadAt` overloads | any |
| EXIF | `FFmpegExif.Parse`, `FFmpegFrameDetails.Exif()` | 8.1 |
| MIME codec string | `FFmpegDemuxer.MimeCodecString` | 8.1 |
| Synchronous decoding | `FFmpegDecoder.ReceiveFrame(frame, synchronous)` | 8.1 |
| Encoder reconfiguration | `FFmpegRecorder.Reconfigure` | 9.1 |
| Bitstream filter graphs | `FFmpegBitstreamFilterGraph` | 9.1 |
| HDR gain maps | `FFmpegGainMap` (ISO 21496-1 round trip, validation, frame side data) | 9.1 |
| Downmix matrices | `FFmpegDownmixMatrix` | 9.1 |
| DSD | `FFmpegDecoder.Open(..., nativeDsd: true)`, `AVSampleFormat.Dsd`, `FFmpegFeatures.NativeDsd` | 9.1 |
| Windows handle input | `FFmpegDemuxer.OpenHandle(SafeFileHandle)`, `FFmpegFeatures.HandleInput` | 9.1, Windows |
| Stream groups | `FFmpegDemuxer.StreamGroups` | any (newer group types need newer FFmpeg) |
| Typed filters | `FFmpegNewFilters`: `ColorDetect`, `LatticePal`, `Whisper`, `GainMap` | the filter's release |

## Added to MediaToolkitNet.Mpv

mpv's node API: `MpvNode`, `MpvPlayer.GetPropertyNode` / `SetPropertyNode` / `CommandNode` (named arguments and
command results), and typed readers `GetTracks`, `GetChapters` and `GetMetadata`, `ObserveProperty`, `GetCommands` / `GetPropertyNames` / `HasCommand` / `HasOption` (what this mpv can do), `Failed` for a file
mpv could not play, `AddHook` (`on_load` and the other mpv hooks, with `Defer` / `Continue`), `CommandNodeAsync` / `CommandAsync` (asynchronous
commands with cancellation), `Open(Stream)` and `RegisterStreamProtocol` (mpv reads a .NET stream or a protocol you define through `stream_cb`), and
`TakeScreenshot` (mpv's `screenshot-raw`: a frame
after mpv's filters, scaling and subtitles, as BGRA, RGBA, BGR0 or 16-bit RGBA). Tested on Windows (libmpv from
winget) and Debian (client API 2.5).

## Tested

Windows 11 with FFmpeg 9.1 (a development build) and 9.0.1, and Debian 13 with FFmpeg 7.1.5. Features missing from a
build skip their tests there. Every new struct layout is confirmed at run time and the feature turns itself off when
the check fails. Stream group membership is cross-checked against the context's own streams.

## Known limits

- `Reconfigure` accepts only options FFmpeg marks as changeable at run time. FFmpeg 9.1 crashes on the others
  (a NULL dereference in `avcodec_encode_reconfigure`), so they are refused before the call.
- A bitstream filter graph takes graph filters only (`lcevc_merge`, source, sink); classic filters are refused.
- DSD is decoder-level only: the shared `SampleFormat` has no DSD value, so readers, recorder and transcoders stay PCM
  (DSD files still decode to float there, as before). FFmpeg has no PCM to DSD conversion.
- Tile grid and layered video group parameters were not tested against a real file; IAMF groups were.
- Not covered: Linux and macOS with FFmpeg 8 or 9.
