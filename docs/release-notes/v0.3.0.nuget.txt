MediaToolkit.NET 0.3.0 - the transcoding release.

A file can now be probed, converted and read frame by frame. A conversion is
described once, as a TranscodeRequest, and run by whichever backend can do it:
FFmpeg is asked first, then GStreamer, then mpv. Each says what it cannot do
before anything is written, and when all refuse the exception carries every
refusal.

The README on this page covers what the library does and what it needs at
runtime. These notes cover only what is specific to this release.

ADDED

- Transcoding API (MediaToolkitNet.Abstractions): TranscodeRequest, OutputStream
  (copy, drop, re-encode, convert subtitles, burn them in), StreamSource
  selectors, VideoOutputSettings and AudioOutputSettings, typed video and audio
  filters, TranscodePlan with the rules every backend shares, IMediaTranscoder
  with Validate and RunAsync, progress, cancellation that deletes the partial
  file, and TranscodeRejectedException listing every issue.
- IMediaProber and MediaInfo: container, duration, streams with codec, language,
  title and flags, tags and chapters. Streams are numbered in container order on
  every backend.
- Subtitle codecs in MediaCodec (SubRip, Ass, WebVtt, MovText, DvdSubtitle, Pgs)
  and ISubtitleRecorder, which FFmpegRecorder implements.
- MediaToolkitNetBackends.Probe, CreateTranscoder and TranscodeAsync.
- FFmpeg: FFmpegTranscoder (stream copy, re-encoding through libavfilter,
  several inputs, subtitle conversion, burn-in through libass, trims, tags,
  chapters), FFmpegProber, FFmpegMediaReader for decoded frames in order or at a
  time in the format asked for, and FFmpegMuxer at the packet level.
- GStreamer: GStreamerProber on GstDiscoverer, and GStreamerTranscoder, which
  builds one pipeline from the plan: copy and re-encode of video and audio from
  any number of inputs, text burn-in, trims and tags.
- mpv: MpvProber, and MpvTranscoder on mpv's encoding mode: one video and one
  audio track re-encoded, subtitles burned in, trims and tags.
- Sample commands: probe with a backend name, transcode (with --vencoder and
  --aencoder), read, mpv-args and gst-args. encoders now lists video encoder
  MFTs too.

CHANGED

- GStreamerBackend.Capabilities is Probing | Transcoding instead of None.
- Probe and CreateTranscoder try FFmpeg, then GStreamer, then mpv.
- MediaToolkitNet.Mpv references MediaToolkitNet.FFmpeg for the encoder, muxer
  and filter names they share. No FFmpeg library is loaded unless the FFmpeg
  backend is used.

FIXED (defects of earlier releases found by running the code)

- Media Foundation could not record video: the GUIDs of MF_MT_INTERLACE_MODE and
  MFT_CATEGORY_VIDEO_ENCODER were wrong. Every GUID has been checked against the
  Windows SDK headers, and the camera records to H.264 and HEVC.
- A bit rate of 0 overwrote the encoder's own default instead of leaving it to
  the encoder. Media Foundation's H.264 encoder refused to start at 0.
- libavfilter audio graphs failed on every series: abuffer takes
  channel_layout, not ch_layout.
- FFmpegDecoder reported zero audio channels.
- Three GstMessageType values were wrong; the GstMessage::type probe caught it.
- GStreamerSink.NegotiatedFormat was always empty, and a pull asked for the
  wrong kind of frame dropped the sample silently. Planar audio is now
  delivered.
- gst_plugin_feature_get_name is a macro and was bound as a function.

VERIFIED BY RUNNING (Debian 13, FFmpeg 7.1.5, GStreamer 1.26.2, libmpv 2.5)

- All 206 unit tests and 85 integration tests pass, three runs in a row. The
  integration tests read every backend's output back with the FFmpeg prober and
  reader, so no backend checks its own work.
- FFmpeg: remux, subtitle conversion with timing identical to ffmpeg's own,
  container changes, trims that cut straddling cues at both ends, scaling, frame
  rate, CRF, resampling for Opus, burn-in checked by luma, VP9 with WebVTT in
  WebM.
- GStreamer: the prober agrees with FFmpeg's; encodes into MP4, Matroska and
  WebM; copies with and without a trim; burn-in from the same file and from a
  separate SRT.
- mpv, through libmpv: the prober agrees with FFmpeg's and reads a bare SRT or
  ASS file; encodes scaled and trimmed; burn-in from the same file and from a
  separate SRT; copying refused with the reason. An encoder mpv lacks, or one
  that cannot open, is now refused or reported instead of producing a file
  without that stream or stalling.
- Windows 11 with FFmpeg 7.1.5 (LGPL) and libmpv 2.5: remux, subtitle
  conversion, H.264 through h264_nvenc, libopenh264 and h264_mf, VP9 in WebM,
  burn-in through libass from an absolute Windows path with a comma, quotes and
  brackets in it; mpv encodes and burn-in; Media Foundation camera recording to
  H.264 and HEVC.

NOT EXERCISED YET - PLEASE READ BEFORE DEPENDING ON THIS

- mpv playback, and libmpv other than 2.5.
- FFmpeg 8 and 9 transcoding: the new offsets were checked against their
  headers, not by running.
- GStreamer other than 1.26.

KNOWN LIMITATIONS

- GStreamer cannot write subtitles as a stream: its muxers take plain UTF-8 and
  its parsers produce Pango markup. The transcoder refuses and names FFmpeg.
- GStreamer 1.26's matroskamux writes tag values containing spaces serialised,
  and writes the input's chapters whatever the request says and untrimmed. The
  transcoder warns about both.
- mpv copies nothing, writes one video and one audio track, and no chapters.
  In MP4 it writes the audio stream first.
- Burn-in is text only on FFmpeg and GStreamer. PGS can be copied but not
  produced.
- The GStreamer backend binds the Linux library names, so it is unavailable on
  Windows and macOS even where GStreamer is installed.
- Media Foundation video recording needs a video encoder MFT, which Windows N
  without the Media Feature Pack lacks; the recorder says so.
- MacOSBackend cannot write files, FFmpegPlayer only decodes, and only the mpv
  client API is wrapped, not its render API.
